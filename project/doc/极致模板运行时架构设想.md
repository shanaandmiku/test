# 极致模板运行时架构设想

## 1. 最终形态

目标形态是一个可编译、可执行、可导出的模板运行时：

`数据源/项目配置 -> 模板运行时 -> 场景 IR -> 预览/导出后端`

系统固定分为 4 层：

1. 数据层
2. 模板运行时与编译层
3. 场景 IR 层
4. 渲染与导出后端层

## 2. 分层结构

### 2.1 数据层

数据层负责统一模板运行时的输入上下文。

```ts
type DataContext = {
  globals: Record<string, unknown>
  params: Record<string, unknown>
  tables: Record<string, Array<Record<string, unknown>>>
}
```

输入来源可以包括：

- 编辑器内手工填写的数据
- 导入的 JSON
- 表格数据
- 外部接口返回的数据
- 模板参数

### 2.2 模板运行时与编译层

模板运行时负责接收：

- 模板包
- 数据上下文
- 用户配置

并输出统一的场景 IR。

这一层包含的职责：

- 读取模板 manifest
- 读取参数 schema
- 参数默认值补齐
- 数据绑定
- 条件显示
- 循环展开
- 样式变量替换
- 动态 scene 生成
- 行为脚本执行
- 时间轴编译

### 2.3 场景 IR 层

场景 IR 是运行时和渲染后端之间的统一中间表示。

```ts
type MovieIR = {
  meta: MovieMeta
  scenes: SceneIR[]
}

type SceneIR = {
  id: string
  duration: number
  layers: LayerIR[]
}

type LayerIR =
  | TextLayerIR
  | ShapeLayerIR
  | ImageLayerIR
  | VideoLayerIR
  | AudioLayerIR
  | GroupLayerIR
  | ComponentLayerIR
```

### 2.4 渲染与导出后端层

同一份 IR 对应多个后端：

- Pixi 预览后端
- 帧渲染后端
- 视频编码后端
- 后续扩展的其他后端

## 3. 模板包结构

模板使用模板包形态组织。

```text
template-package/
  manifest.json
  schema.json
  layout.json
  styles.json
  assets/
  scripts/
    lifecycle.ts
    data-transform.ts
  components/
    chart.grouped-column.json
    chart.ranking-bar.json
```

各文件职责：

- `manifest.json`
  - 模板 id、版本、标签、入口、依赖能力、默认分辨率
- `schema.json`
  - 模板暴露给编辑器的参数定义
- `layout.json`
  - 场景树、图层结构、时间轴、布局信息
- `styles.json`
  - 颜色、字体、字号、间距、主题变量
- `assets/`
  - 图片、音频、视频、遮罩、装饰资源
- `scripts/`
  - 生命周期、数据变换、复杂行为逻辑
- `components/`
  - 模板内复用组件或图表组件配置

## 4. 元素系统

### 4.1 基础元素

```ts
type BaseElementKind =
  | 'text'
  | 'image'
  | 'video'
  | 'audio'
  | 'shape.rect'
  | 'shape.circle'
  | 'shape.line'
  | 'shape.path'
  | 'group'
  | 'mask'
  | 'filter'
  | 'component'
```

### 4.2 高级组件

通过 `component` 承载高级语义元素：

- `chart.grouped-column`
- `chart.ranking-bar`
- `progress-bar`
- `title-card`
- `credits`
- `speaker-layout`

## 5. 行为系统

行为系统分为 3 档。

### 5.1 表达式层

用于轻量绑定和简单计算。

```txt
{{ item.value / maxValue * 100 }}
```

### 5.2 声明式数据变换层

内置数据操作：

- `filter`
- `sort`
- `map`
- `groupBy`
- `aggregate`

### 5.3 脚本 hook 层

用于复杂数据逻辑、复杂布局和复杂动画。

```ts
export function transformData(ctx) {}
export function buildScenes(ctx) {}
export function beforeRender(scene, ctx) {}
export function onTick(node, time, ctx) {}
```

## 6. 沙箱边界

模板行为脚本运行在受控环境内，默认限制如下：

- 不直接访问 `window`
- 不直接访问宿主文件系统
- 不直接发起任意网络请求
- 只通过受控上下文读取数据
- 支持超时
- 支持中断
- 支持结果缓存

推荐运行位置：

- `Web Worker`
- 表达式解释器
- 隔离执行环境

## 7. 模板驱动编辑器

编辑器由模板参数 schema 驱动。

```json
{
  "groups": [
    {
      "title": "基础信息",
      "fields": [
        { "id": "title", "type": "text" },
        { "id": "subtitle", "type": "textarea" },
        { "id": "theme", "type": "select" }
      ]
    }
  ]
}
```

编辑器职责：

- 渲染字段面板
- 编辑原始数据
- 显示预览
- 管理资源
- 执行导出

## 8. 导出链路

导出流程固定为：

`IR -> 帧渲染 -> 编码 -> 封装`

导出层要求：

- 固定 fps
- 精确时长
- 音视频同步
- 离屏渲染
- 逐帧输出
- 编码器接入

浏览器侧可采用：

- Pixi/Canvas 渲染帧
- WebCodecs 编码
- 音频单独混流
- 封装成 mp4/webm

## 9. 与 JSON2Video 的关系

JSON2Video 用于参考外层组织方式：

- `movie -> scenes -> elements`
- 时间轴组织
- 场景动态生成
- 数据驱动模板

内部协议使用自定义的场景 IR，不直接使用 JSON2Video 原协议。

## 10. 演进顺序

### 第一阶段

将现有模板从：

`ProjectRecord -> Pixi`

改为：

`ProjectRecord -> Clip IR`

### 第二阶段

在测试环境实现最小模板 JSON，先支持：

- `text`
- `group`
- `rect`
- `chart.grouped-column`
- `chart.ranking-bar`

### 第三阶段

加入：

- 表达式
- 条件显示
- 简单循环

### 第四阶段

加入：

- 声明式数据变换
- 模板包 manifest/schema
- 模板驱动面板

### 第五阶段

加入：

- 脚本 hook
- 行为沙箱
- 高级导出链路
