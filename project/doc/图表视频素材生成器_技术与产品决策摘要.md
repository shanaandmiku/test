图表视频素材生成器
技术与产品决策摘要
基于本轮讨论整理：面向专业剪辑人员的数据动画素材工具
一句话结论
这个产品应定位为“面向视频时间线的数据动画素材生成器”。在浏览器离线运行的前提下，渲染层优先选 Canvas / PixiJS，编辑器层使用 Vue，整体动画使用 GSAP 实现；默认交付视频素材，专业导出再补充透明视频与帧序列。

1. 产品定位
定位建议：不是视频编辑器，也不是普通图表工具，而是“数据驱动的视频素材生成器”。
•	核心目标是把结构化数据快速转成可直接塞进剪辑时间线的动态图表镜头。
•	主要用户并非纯数据分析人员，而是剪辑、包装、内容制作和商业演示相关人员。
•	产品价值不在于“图表会动”，而在于“产出可直接用、少返工、风格统一的素材”。
2. 从专业剪辑人员视角看，真正需要什么
•	需要的是“可直接用的素材”，而不是一个只能展示图表的页面。
•	素材要能服务镜头叙事：突出重点、控制节奏、留出停留帧，方便旁白和剪切点。
•	素材必须能统一风格：字体、颜色、层级、动效不能像办公软件导出。
•	修改成本要低：改数字、改标题、改比例、改尺寸时不应整段重做。
•	要兼容工作流：便于进入 Premiere、Resolve、FCP、AE 等后期流程。
专业剪辑人员最关心的需求可归纳为：
维度	他们想要的结果	原因
交付形态	能直接进入时间线	减少中间转换和返工
画面节奏	有入场、表达、停留	方便接旁白、音乐与切点
风格控制	可套品牌与片子风格	避免“贴进去像外来素材”
可编辑性	改数据不重做动画	客户改需求是常态
导出兼容	多尺寸、多格式、透明背景	便于复用到不同项目与平台
3. 推荐的素材形态
•	成品型素材：一整段已完成动画的图表视频镜头，适合直接插片。
•	透明叠加素材：仅保留图表、数字和标签，便于叠加到人物或实拍画面上。
•	分层素材：图表层、数字层、标题层、高亮层拆开，适合后期继续精修。
•	模块型素材：将标题入场、图表建立、重点高亮、结尾停留拆成可拼接模块。
最理想的单段素材结构：
•	开头干净：从空画面或简洁框架建立。
•	中间有信息推进：逐步呈现，而不是所有元素同时乱跳。
•	结尾稳定停住：最后保留 0.5–2 秒完整信息状态，方便剪辑切出。
•	不抢戏：服务内容表达，而非用复杂动效喧宾夺主。
4. 导出策略结论
结论：默认导出视频；高级选项再提供透明视频与图片帧序列。
•	默认视频最符合剪辑人员工作流：可直接拖入时间线、裁切长度、接转场与字幕。
•	透明视频适合图表叠加场景，是专业工作流里很高价值的交付形态。
•	PNG 帧序列更适合高级后期和合成流程，但不应成为第一默认选项。
建议分层级提供导出能力：
•	P0：MP4 / MOV 视频导出。
•	P1：支持透明背景的视频导出。
•	P2：PNG 帧序列等高级后期导出。
5. 前端渲染技术选型结论
主判断：主渲染层更适合 Canvas，而不是 DOM。DOM 更适合做编辑器 UI，不适合作为高频视频帧渲染主方案。
•	Canvas 更符合“按时间轴生成一帧一帧画面”的模型。
•	动画、遮罩、高亮、数字滚动等重绘型内容更适合 Canvas。
•	后续若需要 Worker / OffscreenCanvas 优化，Canvas 路线更自然。
•	Vue 适合做面板、数据表、模板库、参数编辑，不适合承担逐帧渲染。
因此，推荐架构是：
•	Vue 3 + DOM：应用层、编辑器层。
•	Canvas / PixiJS：主渲染层。
•	可选 DOM / SVG 覆盖层：仅用于编辑态的辅助线、选框、锚点等交互。
6. PixiJS 与 GSAP 的判断
判断：PixiJS 做渲染、GSAP 做整体动画编排，这是当前阶段最合适的组合；真正需要控制好的是图表对象模型、动画约定和导出链路。
•	PixiJS 适合做统一的 2D 场景树，便于组织图表、文本、遮罩和装饰元素。
•	GSAP 适合承担镜头级 timeline、局部补间、节奏控制和重点高亮这类动画任务。
•	首版完全可以把整体动画建立在 GSAP timeline / tween 之上，以更低成本完成模板验证和交付验证。
•	真正的难点在于图表节点结构、文本系统、模板复用方式，以及如何保证预览与导出使用同一套动画参数。
7. 如果由我来选：推荐方案
模块	建议选择
应用层	Vue 3（面板、数据、模板配置、导出控制）
渲染层	PixiJS 作为主渲染引擎
动画系统	GSAP timeline / tween，统一驱动预览动画与导出动画

我的最终偏好是：PixiJS 做渲染，Vue 做编辑器，GSAP 负责整体动画编排与补间控制。
•	原因 1：素材生成器更像“可控渲染器”，而不是网页动画播放器。
•	原因 2：GSAP 已足够覆盖首版所需的入场、强调、停留、节奏控制等镜头动画需求。
•	原因 3：第一版更应该优先验证模板能力和交付链路，而不是额外投入做更重的动画抽象。
8. 建议的第一版边界
•	先做“素材生成器”，不要做大而全的视频编辑器。
•	先支持常见图表镜头：柱状图、横向条形图、折线趋势、双对象对比。
•	先提供标准成片版和透明叠加版两种高频交付形态。
•	先保证预览与导出一致，再追求复杂交互编辑能力。
9. 最终总结
综合来看，这个项目最适合被定义为：在浏览器离线运行的、面向专业视频工作流的数据动画素材生成器。
•	产品上：交付的是“可直接进时间线的镜头素材”。
•	导出上：默认视频，高级提供透明视频和帧序列。
•	技术上：Vue 管编辑器，Canvas / PixiJS 管渲染，GSAP 管整体动画。
•	架构上：首版先用 GSAP 统一预览与导出所依赖的动画逻辑，后续再视模板复杂度决定是否需要进一步抽象。
